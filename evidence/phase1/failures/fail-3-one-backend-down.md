# Phase 1 – Failure Demonstrations

Mac 1 = client, Mac 2 = server. Each fault was injected, observed, explained, then reverted.

## 1. Wrong DNS server
- **Fault:** Mac 1's DNS set to `8.8.8.8`
- **Symptom:** `dig app.team1.test` → `NXDOMAIN`, `SERVER: 8.8.8.8`; a TCP check to Mac 2's IP still succeeds
- **Layer:** Application (DNS). The network is fine; public DNS has no `.test` zone (reserved TLD)
- **Fix:** point Mac 1's DNS back to Mac 2
- **Evidence:** `fail-1-wrong-dns-server.png`

## 2. Wrong DNS record
- **Fault:** `address=/app.team1.test/` changed to a non-existent IP, dnsmasq restarted
- **Symptom:** `dig` resolves to the wrong IP; `curl` times out
- **Layer:** DNS data is wrong, so the TCP connection goes to a host that doesn't exist
- **Fix:** restore the correct record and restart dnsmasq
- **Evidence:** `fail-2-wrong-record.png`

## 3. One backend down
- **Fault:** Backend B stopped
- **Symptom:** every response comes from Backend A; no request fails
- **Layer:** Application (upstream). nginx retries via `proxy_next_upstream` and skips B for `fail_timeout`
- **Fix:** restart Backend B
- **Evidence:** `fail-3-one-backend-down.png`

## 4. Both backends down
- **Fault:** both backends stopped
- **Symptom:** DNS, TCP and TLS all succeed, then `HTTP/1.1 502 Bad Gateway`; nginx error log shows `connect() failed (61: Connection refused) while connecting to upstream`
- **Layer:** Application (upstream). The 502 is generated by nginx, not the backends
- **Fix:** restart both backends
- **Evidence:** `fail-4-both-backends-502.png`, `fail-4-nginx-log.png`

## 5. Wrong port
- **Fault:** client connects to `https://app.team1.test:8443`
- **Symptom:** `Connection refused`
- **Layer:** Transport. The host is reachable but nothing listens on 8443, so the OS replies with TCP RST
- **Fix:** use port 443
- **Evidence:** `fail-5-wrong-port.png`
